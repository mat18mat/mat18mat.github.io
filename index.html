Classification d'images de jeux vidéo

Projet annuel · équipe de 4 · 2026
Scraping→ Nettoyage→ Vectorisation→ Six modèles C++→ Évaluation

899 captures de gameplay collectées par scraping et manuellement, puis vectorisées en 3072 features RGB. Six algorithmes d'apprentissage écrits from scratch en C++ — modèle linéaire, classification linéaire, SVM, perceptron multicouche, RBF et k-NN — pilotés depuis Python via une API FastAPI et un client graphique PyQt5.

Deux problèmes de classification distincts sur le même corpus : le genre du jeu (FPS, MOBA, RTS) et son mode (solo ou multijoueur). Chaque axe a ses propres hyperparamètres, optimisés séparément.

C++PythonFastAPI PyQt5NumPyscikit-learn

Chaque algorithme a d'abord été validé sur douze jeux synthétiques à réponse connue — XOR, croix, régressions simples — avant d'approcher le dataset réel. Les erreurs d'implémentation se corrigent sur des données maîtrisées, pas noyées dans 899 images.

Le modèle le plus simple généralise le mieux sur le genre — vingt points d'avance sur le SVM en test, alors qu'il le talonne en entraînement.

Les écarts train/test signalent un surapprentissage : 899 images pour 3072 features, le rapport est défavorable. Le RBF est le cas symétrique — train et test collent à 44 %, il ne surapprend pas parce qu'il n'apprend pas assez.
  • Résolution 32×32 retenue contre 128×128 : 49152 features auraient garanti le surapprentissage à ce volume
  • Partition gérée côté Python — le C++ n'a jamais accès aux données de test
  • Normalisation L2 pour le k-NN, sans quoi les distances sont dominées par l'échelle brute des pixels

Analyse distribuée d'un corpus musical

Projet Hadoop · équipe de 5 · 2026
HDFS→ PySpark→ Nettoyage→ K-means→ Streamlit

Déploiement d'un cluster local complet sous WSL Ubuntu, puis pipeline de bout en bout sur un corpus de 2000 titres décrits par 18 variables audio — de l'ingestion HDFS jusqu'à la restitution web interactive.

Installation complète sous WSL : variables d'environnement, mise en service de HDFS et YARN, résolution des incompatibilités entre YARN et Java 21 via les options d'ouverture de modules.

  • Ingestion du corpus sur HDFS et vérification de l'intégrité
  • Parsing PySpark avec inférence de schéma — typage correct des 18 colonnes
  • Nettoyage : aucune valeur nulle, 59 doublons supprimés, 1941 lignes exploitables
  • Statistiques descriptives et détection des valeurs aberrantes
  • Clustering K-means via Spark ML, directement sur les données distribuées
Le choix de Spark plutôt que pandas n'est pas cosmétique : pandas charge tout en mémoire sur une machine. Spark lit depuis HDFS et distribue le calcul — la même chaîne tient sur 2000 lignes comme sur 200 millions.

Architecture à deux moteurs conteneurisés : MongoDB pour les agrégations de ventes, Neo4j pour les analyses de réseau — co-achats et chaînes de parrainage. Le moteur est choisi selon la nature de la question posée, pas par habitude.
